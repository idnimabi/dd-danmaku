# 自定义弹弹 play API 路由设计

## 目标

保留现有 API 配置界面，使用户可分别启用官方和自定义 API、填写自定义 API 地址和跨域代理前缀、设置请求优先级。请求必须按该优先级依次尝试：自定义 API 没有配置、请求失败或没有搜索结果时，继续尝试官方 API。

默认优先级保持为 `custom`、`official`；已有用户保存的优先级仍然生效。

## 路由与 URL 构造

`dandanplayApi` 是所有弹弹 play URL 的唯一构造入口，负责生成搜索、评论、扩展评论、海报和 `/match` 地址。

每个请求源由一个 API 配置对象表示，包含名称、是否启用、实际根地址和是否使用代理：

- 自定义 API 直接使用用户填写的根地址，绝不拼接代理。
- 官方 API 使用 `https://api.dandanplay.net/api/v2` 作为服务地址；仅在用户填写了“跨域代理前缀”时拼接该前缀。代理前缀默认值为空，不在代码中硬编码具体代理地址。

URL 构造需清理根地址末尾的 `/`，避免双斜杠。

## 请求与缓存行为

自动匹配和手动搜索都调用同一个 API 配置序列。自动匹配按序遇到第一个有结果的 API 即停止；手动搜索合并所有成功源的结果，并把来源写到结果中。

所有匹配结果都保存实际使用的 `apiPrefix`。之后的评论请求优先使用该字段，确保搜索和拉取弹幕来自同一服务。

缓存键继续区分已启用 API 和优先级；变更地址后，用户可通过现有“清除本地匹配缓存”操作移除旧匹配。

## 错误处理与兼容性

单个 API 请求的网络、HTTP 或空结果不终止后续源的尝试。两个源都不可用或无结果时维持现有的匹配失败提示。

自定义 API 仍须提供浏览器可访问的 CORS 响应；官方 API 是否需要代理由用户的页面配置和运行环境决定。

## 验证

为 URL 与路由选择抽取可在 Node 环境执行的纯函数测试，覆盖：

1. 自定义 API 优先且成功时只使用自定义 API。
2. 自定义 API 失败或没有结果时回退至官方 API。
3. 官方 API 仅在用户配置代理前缀时使用代理，默认直连。
4. 搜索和评论 URL 都来自 `dandanplayApi`，并保留实际 API 根地址。
